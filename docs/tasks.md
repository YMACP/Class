# 任务、定时启动与并行课堂

在课堂输入框上方勾选 **任务**，填写任务名称、任务描述和任务目标。老师据此制定验收条件，学生仍独立解决同一道完整问题，最后由老师依据证据验收。专业模式、附件、Jev和校长汇报保持原有职责。

再勾选 **定时**，可在右侧设置启动时间。界面固定使用北京时间（`Asia/Shanghai`），不受电脑时区影响，保存时转换为UTC时间。尚未开始的任务可修改、立即启动或取消。定时任务到点创建自己的课堂，无须等待其他任务结束。

任务开始后，原发送按钮变为停止按钮。点击立即取消当前任务，清理进程和保存记录期间显示“正在停止”；其他并行任务继续运行。运行中仍可通过校长按钮或输入 `/btw 问题` 后按回车提问。

Class本地服务需要保持运行，计算机需要保持唤醒。关闭浏览器页面不停止任务；点击退出服务会停止并保存所有正在运行的任务。重启时，已经错过时间的预约显示“已错过”，由用户选择立即启动或重新安排。已启动的运行不会因重新打开页面而重复执行。

## 并行与隔离

- 每个运行都有独立的老师、学生、Jev、上下文、黑板、证据、工具管理器和续跑快照。暂停、继续、停止、清除和校长汇报均按运行ID执行。
- 点击新建对话可以随时下发另一任务。历史列表保留各自状态，切换查看不会停止后台课堂。
- 新任务的默认目录为配置工作目录下的 `.class-runs/<runId>`。相对路径的输出互不覆盖；明确访问原项目时使用项目根目录中的路径。文件工具拒绝访问其他运行的独立目录。命令行和用户自行提供的外部服务仍按其自身权限工作，不是操作系统级沙箱。
- 已运行任务使用开始时取得的成员、模型凭据、Jev和扩展快照。修改配置影响之后启动的任务。预约保留任务、专业模式定义、成员ID、运行设置和附件；实际启动时读取这些成员当前的模型与凭据以及当前扩展/Jev配置。成员被删除会导致启动失败，可调整配置后手动重试。
- 长期记忆继续共享，通过已有写入队列和数据库事务保存；运行中的原始会话仍按任务归档。
- 独立浏览器和子进程由各运行管理。同一个远端MCP源地址，以及已知共享调试程序适配器，采用运行归属保护。其他课堂使用相同资源时返回占用信息，可以使用其他工具，待资源释放后重试。同一课堂的老师和学生对共享外部资源的操作按顺序执行。

## 存储与恢复

`task-schedules.json` 保存预约与预留的运行ID，不保存成员API密钥。调度器先原子保存启动凭据，再创建运行；遇到不确定的上次启动结果，核对历史记录，不能确定时等待手动处理，不自动重放。

运行记录和加密续跑快照继续使用 `history/` 与 `checkpoints/`。迁移数据目录会先停止调度器，迁移预约、附件和运行记录后重新打开。运行中的任务必须先停止，才能迁移整个数据目录。

## API

| 操作 | 接口 |
| --- | --- |
| 新建对话/任务/预约 | `POST /api/runs`，可选 `taskSpec: {name, description, goal}` 与 `schedule: {at, timeZone}` |
| 查看全部活动课堂 | `GET /api/state` 的 `runs`；`history` 包含已结束和待启动记录 |
| 查看指定课堂 | `GET /api/runs/:id` |
| 暂停/继续/停止 | `POST /api/runs/:id/pause`、`resume`、`stop` |
| 修改尚未执行的预约 | `PATCH /api/runs/:id` |
| 预约立即启动/取消 | `POST /api/runs/:id/start`、`cancel` |
| 删除指定记录 | `DELETE /api/runs/:id` |

`at` 为包含UTC偏移的ISO时间，`timeZone` 为IANA时区名，例如 `Asia/Shanghai`。启动后的任务内容不可通过预约编辑接口改写。
