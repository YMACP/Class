# 记忆管理（1.0.0）

[返回首页](../README.md) · [Windows 数据管理](windows.md) · [开发验证](development.md)

一次 Class 任务对应一个会话。记忆功能默认开启，采用本地 SQLite/FTS5，支持中文关键词和字面子串补充检索；检索本身不需要模型或向量服务，自动提取使用已配置的老师模型。学生并行求解、发现投票、老师否决反馈与持续验收沿用原流程；记忆不增加必经验收阶段。

| 工具 | 能力 |
| --- | --- |
| session_search | 检索历史任务、公开模型回复、实际发送的上下文、工具调用结果和已留存的长文本；返回会话、时间、原文片段与来源引用。支持时间及会话过滤、分页。 |
| session_get | 根据会话 ID 或来源引用查看有权限的原文上下文，支持分页和命中位置定位。 |
| memory_search | 跨会话、跨工作目录查找有权限且已启用的长期记忆，支持用户画像 / Agent画像过滤，并提示使用前评估。 |
| memory_get | 读取有权限且已启用的记忆、来源和有效期；长内容按字符分页。不能凭 ID 绕过暂停或过期状态。 |
| memory_propose | 自动保存有来源的用户画像（user）或 Agent画像（agent），须明确类型，无须用户确认；保留旧工具名，不修改任务权限或代替老师验收。 |
| memory_assess | 使用前记录 usable / uncertain / expired / invalid 判断、理由和可选核验来源；权限允许时将已过期或错误的记忆停用。 |

同一 Class 数据目录中的长期记忆供之后所有会话按需使用，工作目录不再限定可检索的记忆或历史。不同 Class 数据目录仍各自独立，不跨库读取。历史内容由模型按需检索，不会将整个会话库塞进每次提示词。老师可读全组记录；学生可读自己的记录、用户原始任务与共享成果。跨会话共享不改变成员私有记录的权限：原始模型输入、私有审查材料和旧角色私有记忆仍按稳定成员 ID 保护，删除后重建的同名成员不会自动获得旧私有内容。历史工作目录仅作为来源和迁移元数据保留。

“记忆管理”主页面只展示长期记忆，类型分为“用户画像”和“Agent画像”：前者记录用户喜好、偏爱，后者记录可用于后续会话的技能、方法和经验。筛选项为“全部类型 / 用户画像 / Agent画像”，不显示项目筛选或路径。用户可启用、暂停、编辑、设置有效期、删除和按需查看来源原文，不再手动新增；HTTP 新增接口也会拒绝请求。状态统一显示为已启用、已暂停、已失效，过期或被替代的内容归入已失效。空列表只在页面中间显示“暂无记录”，分页按钮位于底部。

刷新左侧的齿轮打开“记忆设置”，保留记忆总开关、统计和“整理记忆”。整理状态统一显示在弹窗右上角，包括会话整理中、记忆整理中、整理失败、整理成功，不罗列逐条作业日志。界面不提供导出、重建索引或会话记录选项；底层历史存储、session_search / session_get、原文读取及维护 API 继续保留。

自动提取随记忆功能开启，不设置候选确认环节。已结束的非演示会话在主任务空闲时调用当前老师模型，从公开来源生成并启用两类画像；没有配置可用老师时显示等待状态。提取和整理可能产生模型费用，无需额外密钥；单次后台请求最多 60 秒，自动任务失败最多尝试 3 次。单次输入有长度限制，长会话优先保留最近的公开结果，不能保证提取全部内容。“整理记忆”从整个库选择已启用画像，不受当前工作目录影响；共享内容和各成员私有内容分别调用模型，私有组的结果固定保留给原成员，不依赖模型自己声明共享权限。新任务开始会暂停后台模型整理，中断队列在重启后恢复；成功提取状态随会话保存，不因队列日志轮换反复提取。

启用只表示允许检索，不表示内容已经核实。Agent 提示词要求每次使用前检查时间、适用范围、来源及当前证据，必要时调用 session_search / session_get 加载历史上下文，并用 memory_assess 记录判断。uncertain 表示本次使用前仍需核验，不会自动把记忆全局暂停；学生对公共记忆的评估仅作为本次判断，老师或所属角色可在权限范围内停用过期、错误记忆。评估结论仍是模型判断，不能代替当前证据或老师验收；检索、保存和评估均不会解锁未修改答案的重复送审。

旧用户记忆迁移为用户画像，旧项目知识、角色经验和技能迁移为 Agent画像；保留原 ID、来源、有效期和成员归属，不凭改名声称旧内容已重新核实。旧版候选和已确认记忆升级为启用状态，原先关闭的记忆总开关保持关闭。自动保存按类型、成员归属和规范化正文哈希跨工作目录去重，保留相同内容已有的暂停、失效和有效期；已保存的删除哈希继续阻止相同内容换 ID 或换工作目录复活。该保护不识别同义改写，也无法还原早期内部版本删除时未保存的正文。用户可修正已有记忆的内容和来源，自动整理不能替用户重新启用暂停内容或删除原始会话。

关闭记忆后，新任务不声明这些工具；已保存数据保留。索引写入、搜索或后台整理失败只报告记忆错误，不将其升级为任务引擎的存储失败。原任务档案本身的写入失败仍按原有规则处理。索引正在补建或报错时，检索结果带有状态提示，空结果不等于不存在历史信息。

数据保存在所选 Class 数据目录内：`memory/memory.sqlite` 保存原文索引及长期记忆，`memory/settings.json` 保存开关，`memory/jobs.json` 保存整理队列，`memory/projects.json` 保存迁移归属；`memory-deletions.json` 独立保存会话删除记录。新任务的可见模型交互另存 `history/<runId>/conversations.jsonl`，不保存私有 thinking、图片 base64 或已知密钥。数据库含用户会话内容，属于正式数据，不能当作可随意删除的缓存。

数据目录迁移会关闭数据库后整体复制，重开时自动衔接被一并移动的默认工作目录及子项目；外部项目不改变归属。删除会话会删除对应索引和依赖来源的派生记忆，重启或重建索引不能恢复已删除内容；单独删除某条记忆不删除原始会话。重建操作只重建可用的全文索引，不承诺修复损坏的数据库文件。

首次启动会补建实际留存的旧任务档案。旧记录没有工作目录时保留未知来源标记，不影响按身份授权检索；旧版未保存的模型完整交互无法补造。命令行把记忆保存在 `--output-dir` / `CLASS_RUNS_DIR` 对应目录中，同一输出目录中的会话可跨工作目录检索；任务结果保存后才运行后台提取，提取失败不改变原任务结果。使用 `--no-memory` 可关闭。旧命令行目录没有会话元数据的运行不自动导入。

记忆验证：`npm test` 覆盖检索、权限、原文、删除、迁移及工作流回归；构建后运行 `npm run verify:memory`，使用本地模拟模型验证实际 EXE 重启后的跨会话工具调用与连续审查；`npm run verify:ui` 使用独立数据目录、无头 Edge/Chrome 和本机假模型验证管理界面，不接触正式配置或真实模型。验证脚本保存在 `tests/release/`，默认针对源码同级发布目录中的 EXE。
